# sim2real-deploy

强化学习策略从仿真到实机的部署链路。每台机器人一个目录，训练侧与部署侧在结构上严格分离。

## 设计原则

**这个仓库最重要的边界，是训练侧和部署侧之间那道接缝。目录结构把它做成物理隔离，而不是靠自觉。**

```
robots/<机器人>/
├── training/    依赖 isaaclab，装在训练环境
└── deploy/      零 isaaclab 依赖，装在部署环境
```

两者是**独立的 Python 包，各有 pyproject.toml**。部署环境里根本没有 `isaaclab`，因此「部署代码误引用了仿真框架」这件事在物理上不可能发生——写错了连装都装不上。

这不是洁癖。RL 策略上实机失败，绝大多数不是控制没学好，而是**部署端没能精确复现训练端喂给策略的那个输入分布**。观测顺序、关节映射、归一化系数任何一处对不上，仿真里都完全正常，上电就废。所以：

- 两侧之间**只允许**通过三样东西通信：策略权重文件、观测契约表、关节映射表
- 契约表由脚本从配置**自动导出**，不人肉誊写
- 契约文件**进版本库**（尽管是生成物），因为行为异常时第一件事就是 `git diff` 它
- sim2sim 与实机**共用同一份**观测拼装、关节映射、安全逻辑，只替换读写后端——否则验证的和运行的不是同一个东西，验了等于没验

## 结构

```
docs/contracts/          接缝契约（自动生成，进 git）
tools/                   跨机器人通用工具
robots/<机器人>/
├── assets.toml          资产路径、出处、转换命令、拍板参数
├── assets/              派生资产（USD、权重），gitignore
├── training/            Isaac Lab 任务定义
├── deploy/              部署运行时（可独立安装到机载计算机）
└── tools/               该机器人专用：导出、比对、验证
```

资产（URDF、网格、USD、权重）**不进版本库**，`assets.toml` 记录出处与再生成方法。

## 环境

| 用途 | 环境 | 关键依赖 |
|---|---|---|
| 训练 | `env_all_pro` | Python 3.11、Isaac Sim 5.1、Isaac Lab 0.54.3、torch 2.7.0+cu128、rsl_rl |
| 部署验收 / sim2sim | `d1_deploy` | Python 3.11、torch 2.7.0 CPU、numpy、mujoco。**不装 isaaclab、不装 rsl_rl** |
| 机载 | 待定 | 见各机器人 `assets.toml` |

`d1_deploy` 环境本身就是交付验收工具：策略能在这个没有仿真框架的环境里加载成功，才算真的脱得开。
